Apply multiple sequential edits to a single file in one atomic call.

Usage:
- Prefer this over multiple `edit` calls whenever you have two or more patches to the same file — one batched call has lower latency than many sequential ones.
- This tool batches patches to ONE file. When a change spans several files, send one `edit` or `multi_edit` call per file and issue those calls in parallel in a single message.
- You must use `read` at least once on the target file in the conversation before calling multi_edit.
- The `edits` array is applied SEQUENTIALLY: each edit's `oldString` is matched against the buffer produced by all previous edits in this call. Order your edits so each oldString is unambiguous at its point in the sequence.
- ATOMIC: if any edit fails (oldString not found, multiple matches, or oldString === newString), the entire call aborts and the file is NOT modified.
- Per-edit `replaceAll: true` swaps every occurrence of that pair (useful for rename).
- First-edit `oldString: ""` creates a new file with `newString` as the seed; subsequent edits then patch that buffer. The file must NOT already exist in creation mode.
- Whitespace / indentation rules are identical to `edit`: oldString must match the file content exactly.
- Group related patches into a single multi_edit call. If you only have one patch, use `edit` instead.
