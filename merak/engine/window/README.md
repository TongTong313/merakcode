# Context budgets

The engine reads context and output limits from the model catalog. It reserves `max(maxOutput / 4, 8192)` tokens for output, rebuilds above 90% of the window, targets 60%, and keeps at least the newest four user turns. The estimate includes the reserved output. The latest input is never silently truncated. `MRK-4002` rejects a request that cannot fit while preserving the required turns; `MRK-4003` reports a failed summary and retains the original messages.

The counter uses a standard-library heuristic for text, tool arguments and schemas, reasoning and tool results. Three independently specified `cl100k_base` examples from the [OpenAI cookbook](https://developers.openai.com/cookbook/examples/how_to_count_tokens_with_tiktoken) have a 35% test tolerance. This is a sample tolerance, not an accuracy guarantee for arbitrary text or every tokenizer. Provider-reported total input calibrates the estimate separately for each provider/model pair. Cached tokens are already included in total input and are not added again.

Images reserve at least 4096 tokens before calibration; embedded image bytes can increase that allowance. Text documents use the text heuristic. Binary documents reserve at least 4096 tokens and otherwise one token per byte. These are conservative starting estimates, not provider tokenizers or a bound for every compressed document. Tool-result media use the same estimates.

Rebuild considers complete oldest turns in order. A candidate must leave room for the summary's mandatory headings and recent turns. The model gets the remaining summary allowance, capped at 2048 tokens. The summary request reuses the original system, tools and replaced prefix, followed by a fixed instruction. It performs one model request and never executes returned tool calls. Missing headings, truncated output, a request that exceeds the model window, or a summary that exceeds the target fails without replacing history. An unfinished tool round cannot be rebuilt.

`session.rebuilt` records the replaced message range, prior event position, previous summary ID, new summary ID, summary and usage. Folding that event replaces the prefix and removes reasoning from retained messages. The event stream still contains the originals. `session.budget` records each conversation or summary request, including reserve, component estimates, the preceding conversation's cache usage and coded failures. Failed summary usage is recorded for replay and cost accounting.

`model.Request.MaxTokens` carries the output reservation. The compatible adapter uses [OpenAI's `max_completion_tokens`](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) or [compatible providers' `max_tokens`](https://api-docs.deepseek.com/api/create-chat-completion/). Offline HTTP fixtures verify the request fields; no paid model calls run in the test suite.
