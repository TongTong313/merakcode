Go 入门指南：写给熟悉 Python、学过 C/C++ 的 MerakCode 开发者

这份指南的目标：让你能读懂、能审查 AI 写的 Go 代码，也能自己改一些小功能。

每一节都先讲 Go 和 Python 哪里不一样，再给一个和 MerakCode 有关的小例子。用得上 C/C++ 经验的地方，会单独标出来。

示例代码里的注释用中文，是为了方便你读。仓库里的代码注释要用英文。

一句话认识 Go

Go 的写法比 C 简单，运行起来接近 C 的速度，又和 Python 一样有垃圾回收。它编译成一个可以直接运行的文件，不需要像 Python 那样另外装解释器。

  • 和 Python 比：Go 有静态类型，类型错误在编译时就报出来，相当于强制开启了 mypy。Go 没有异常，错误是普通的返回值。
  • 和 C 比：Go 有指针和结构体，语法很像 C。但 Go 不能做指针运算，也不用手动释放内存，没有头文件。
  • 和 C++ 比：Go 没有类继承、函数重载、构造和析构函数，也没有异常。这些功能都用更简单的办法代替，后面会讲到。

  1. 从 go.dev/dl 下载并安装最新的稳定版。
  2. 重新打开终端，运行 go version，确认安装成功。

2. 第一个程序

  1. 新建一个临时目录，比如 D:\code\go-practice\hello。
  2. 在这个目录里运行 go mod init example.com/hello。
  3. 新建 main.go，内容如下。
  4. 运行 go run .。
package main

import "fmt"

func main() {
	fmt.Println("hello, merak")
}
  • package main：这个文件属于 main 包。main 包会编译成一个可以运行的程序。
  • import "fmt"：引入标准库的 fmt 包，它负责格式化输出，相当于 Python 的 print 加字符串格式化。
  • func main()：程序从这里开始运行，和 C 的 main 一样。Python 里对应 if __name__ == "__main__":。
  • 代码块用大括号，不靠缩进。缩进统一用制表符，由 gofmt 自动处理。语句结尾不写分号。

4. 基本语法

4.1 变量和零值

零值指变量声明了但没赋值时的默认值。Go 里每种类型都有零值。所以普通的字符串、数字不会是 None，空字符串就是 ""。这一点和 C 不同：C 的局部变量不初始化时，里面是随机值。 

var name string     // 零值是 ""
var count int       // 零值是 0
var done bool       // 零值是 false
model := "deepseek" // 自动推断为 string
const maxSteps = 50
类型 零值
数字 0
string ""
bool false
指针、切片、map、接口、函数、channel nil
结构体 每个字段取各自的零值

4.2 函数和多个返回值

Python 返回多个值时，其实返回的是一个 tuple。Go 的函数本身就能返回多个值。最常见的写法是：最后一个返回值是 error。 

func divide(a, b float64) (float64, error) {
	if b == 0 {
		return 0, errors.New("divide by zero")
	}
	return a / b, nil
}

result, err := divide(6, 3)
if err != nil {
	return err
}
fmt.Println(result)

Go 没有默认参数和关键字参数。参数多的时候，习惯传一个结构体：

type RunOptions struct {
	Dir     string
	Timeout time.Duration
}

func Run(command string, options RunOptions) error { ... }

Run("git status", RunOptions{Timeout: 3 * time.Second}) // 没写的字段取零值

4.3 切片和 map

切片相当于 Python 的 list，但元素类型必须一致。用 C 的话说，切片是“指向一块数组的指针，加上长度和容量”。map 相当于 dict。 

tools := []string{"read", "write"}
tools = append(tools, "bash") // append 返回新切片，要重新赋值
for i, tool := range tools {  // 相当于 Python 的 for i, tool in enumerate(tools)
	fmt.Println(i, tool)
}

prices := map[string]float64{"deepseek": 1.5}
prices["qwen"] = 2
price, ok := prices["kimi"] // 找不到时不报错：ok 是 false，price 是零值 0
if !ok {
	fmt.Println("no price")
}
fmt.Println(price)

Python 的 d["kimi"] 找不到会抛 KeyError。Go 不会，所以要用 ok 判断有没有找到。

4.4 结构体和方法

Go 用结构体加方法代替 class。方法就是带“接收者”的函数。接收者写在 func 和方法名之间，作用相当于 Python 的 self。 

type Session struct {
	ID       string
	Messages []string
}

// 相当于 __init__：Go 没有构造函数，习惯写一个 NewXxx 函数
func NewSession(id string) *Session {
	return &Session{ID: id} // 返回局部变量的地址，在 Go 里是安全的
}

// 指针接收者 *Session：方法里能修改 s
func (s *Session) Add(message string) {
	s.Messages = append(s.Messages, message)
}

// 值接收者 Session：拿到的是一份复制，只适合只读
func (s Session) Count() int {
	return len(s.Messages)
}

s := NewSession("abc")
s.Add("hi")
fmt.Println(s.Count()) // 1

怎么选接收者：方法要修改结构体，或者结构体比较大，就用指针接收者。拿不准时用指针接收者。同一个类型的方法最好统一用一种。

Python 里对象赋值传的是引用。Go 里结构体赋值和传参都会复制一份，这一点和 C 一样。想共享同一份数据，就传指针。

4.5 指针

  • 语法和 C 一样：&x 取得 x 的地址，*p 取出指针指向的值。
  • 和 C 不同的地方：不能做指针运算；不用手动释放内存；可以放心返回局部变量的地址。
  • 用指针的三个常见原因：要修改原来的值；结构体太大，不想复制；要表示“可能没有值”。指针可以是 nil，作用类似 Python 的 Optional[X]。

4.6 谁能用这个名字

  • 首字母大写的名字，其他包可以用，比如 Session、NewSession。
  • 首字母小写的名字，只能在本包里用，比如 session、newID。
  • 这和 Python 的 _name 约定不同：Go 是编译器强制的，别的包用了会编译失败。
  • 结构体字段也一样。encoding/json 只能读写首字母大写的字段。

4.7 控制流

// if 可以先执行一句，再判断；条件不加括号
if err := save(s); err != nil {
	return err
}

// Go 只有 for 一种循环，没有 while
for i := 0; i < 3; i++ { // 和 C 一样
}
for i := range 3 { // Go 1.22 起可以 range 一个整数，相当于 Python 的 range(3)
	fmt.Println(i)
}
for !done { // 相当于 while not done
}
for { // 相当于 while True
	break
}

// switch 不需要 break，也不会自动往下执行（和 C 不同）
switch level {
case "read":
	fmt.Println("read only")
case "edit", "full":
	fmt.Println("can write")
default:
	fmt.Println("unknown")
}

4.8 用 const 和 iota 代替 Enum

type Level int

const (
	ReadOnly Level = iota // 0
	Edit                  // 1
	Full                  // 2
)

写法和 C 的 enum 很像。iota 在一组 const 里从 0 开始，每行加 1。

5. 错误处理

Go 没有异常，也没有 try/except。出错时，函数把错误当作一个普通的返回值交回来，调用方每次都检查。C 语言靠返回错误码，思路相近，但 Go 的 error 能带上说明文字和原来的错误。

  • 看到 if err != nil 很多，是正常的。它让每个出错的地方都清清楚楚，不会有“不知道从哪里抛出来的异常”。
  • 往上返回错误时，用 fmt.Errorf("做什么: %w", err) 加上说明。%w 会把原来的错误包在里面，作用相当于 Python 的 raise NewError(...) from err。
  • 判断是不是某种错误，用 errors.Is，相当于 except FileNotFoundError。要取出某种错误类型，用 errors.As。不要比较错误信息的文字。
  • panic 相当于一个没人捕获的异常，只用于程序本身的 bug，比如不可能出现的状态。正常的失败都用 error。 
var ErrNotFound = errors.New("session not found")

func Load(id string) (*Session, error) {
	data, err := os.ReadFile(filepath.Join("sessions", id+".json"))
	if errors.Is(err, fs.ErrNotExist) {
		return nil, ErrNotFound
	}
	if err != nil {
		return nil, fmt.Errorf("load session %s: %w", id, err)
	}
	var s Session
	if err := json.Unmarshal(data, &s); err != nil {
		return nil, fmt.Errorf("parse session %s: %w", id, err)
	}
	return &s, nil
}

s, err := Load("abc")
if errors.Is(err, ErrNotFound) {
	// 当作新会话处理
}

5.1 defer

defer 后面的调用，会在当前函数返回前执行。它常用来关闭文件、释放锁。作用相当于 Python 的 with 和 finally，也相当于 C++ 里析构函数做的事。 

f, err := os.Open(path) // Python：with open(path) as f:
if err != nil {
	return err
}
defer f.Close() // 不管后面从哪里 return，都会关闭文件

6. 接口和泛型

6.1 接口：编译时检查的鸭子类型

Python 的鸭子类型是“有这个方法就能用”，但要到运行时才知道对不对。Go 的接口也是“方法对得上就算实现”，不用写继承或声明，而且编译时就检查。它最接近 Python 的 typing.Protocol。

所以测试时可以随手写一个假实现，不需要 mock 库。

type Model interface {
	Reply(ctx context.Context, prompt string) (string, error)
}

// 测试用的假模型：有 Reply 方法，就自动实现了 Model
type fakeModel struct{ reply string }

func (m fakeModel) Reply(ctx context.Context, prompt string) (string, error) {
	return m.reply, nil
}

func Ask(ctx context.Context, model Model, question string) (string, error) {
	return model.Reply(ctx, question)
}

answer, err := Ask(context.Background(), fakeModel{reply: "hi"}, "hello")

Go 的习惯有两条：接口要小，一两个方法最好；接口由使用它的包来定义，不由实现它的包定义。

6.2 用接口和类型分支表示“几种之一”

Python 里可能写 Event = Union[TextEvent, ToolEvent]，再用 isinstance 或 match 区分。Go 里的写法如下： 

type Event interface{ isEvent() }

type TextEvent struct{ Text string }
type ToolEvent struct{ Name string }

func (TextEvent) isEvent() {}
func (ToolEvent) isEvent() {}

func show(event Event) {
	switch e := event.(type) { // 相当于一串 isinstance 判断
	case TextEvent:
		fmt.Println("text:", e.Text)
	case ToolEvent:
		fmt.Println("tool:", e.Name)
	}
}

isEvent 是首字母小写的方法，别的包里的类型无法实现它。这样就保证了 Event 只有本包定义的这几种。

6.3 泛型

func Map[T, U any](items []T, f func(T) U) []U {
	out := make([]U, 0, len(items))
	for _, item := range items {
		out = append(out, f(item))
	}
	return out
}

names := Map([]int{1, 2}, func(n int) string { return fmt.Sprint(n) })

这相当于 Python 里用 TypeVar 写的泛型函数，也类似 C++ 的模板，但简单得多。Go 社区习惯少用泛型，只在真的要对多种类型写同一段逻辑时才用。标准库的 slices 和 maps 包已经提供了常用的泛型函数，比如 slices.Contains、slices.Sort。

7. 并发

先说和 Python 最大的不同。Python 有 GIL，多线程不能同时用多个 CPU 核跑 Python 代码；要并发等待网络，通常用 asyncio，而 asyncio 要求函数写成 async def，调用时还要 await。Go 没有这两个限制：

  • Go 的函数直接调用、直接等待，不区分同步函数和异步函数。
  • goroutine 能分布在多个 CPU 核上同时运行。

先记住四个词：

  • goroutine：Go 的轻量级任务。在函数调用前加 go，这个函数就会和当前代码同时运行。它像 asyncio 的 task 一样便宜，开几千个也没问题；又像线程一样能真正并行。
  • channel：goroutine 之间传数据的管道，相当于 Python 的 queue.Queue。一端写入，另一端读出。
  • context：在一组任务之间传递“取消”和“超时”的对象。Python 里没有完全对应的东西，作用接近 asyncio 的任务取消加 asyncio.wait_for 的超时。
  • select：同时等待多个 channel，哪个先有数据就处理哪个。

7.1 同时运行多个任务，等全部完成

这相当于 asyncio.gather。比如协作群里几个成员同时干活：

var wg sync.WaitGroup
results := make([]string, len(members))
for i, member := range members {
	wg.Add(1)
	go func() {
		defer wg.Done()
		results[i] = member.Run(ctx) // 每个 goroutine 只写自己那一格，互不干扰
	}()
}
wg.Wait() // 等所有 goroutine 都调用了 Done

7.2 用 channel 逐行传出子进程的输出

引擎经常要运行一个命令，再把输出一行一行交给别的部分。下面的函数做的就是这件事，Python 里要用 subprocess.Popen 加线程或 asyncio 才能做到。ctx 被取消时，它会停下来，子进程也会被结束。 

func streamLines(ctx context.Context, name string, args ...string) (<-chan string, error) {
	cmd := exec.CommandContext(ctx, name, args...) // ctx 取消时会结束子进程
	stdout, err := cmd.StdoutPipe()
	if err != nil {
		return nil, err
	}
	if err := cmd.Start(); err != nil {
		return nil, err
	}
	lines := make(chan string)
	go func() {
		defer close(lines)  // 写入的一方负责关闭 channel
		defer cmd.Wait()    // 释放子进程资源；示例忽略了它的错误，正式代码要处理
		scanner := bufio.NewScanner(stdout)
		for scanner.Scan() {
			select {
			case lines <- scanner.Text():
			case <-ctx.Done(): // 读的一方不要了，就退出，避免 goroutine 一直卡住
				return
			}
		}
	}()
	return lines, nil
}

ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
lines, err := streamLines(ctx, "git", "log", "--oneline")
if err != nil {
	return err
}
for line := range lines { // channel 关闭后循环结束
	fmt.Println(line)
}

7.3 互斥锁

多个 goroutine 读写同一份数据时，要用锁保护，相当于 Python 的 threading.Lock。Python 的 GIL 会掩盖一部分这类问题，Go 不会，所以更要注意。 

type Counter struct {
	mu sync.Mutex
	n  int
}

func (c *Counter) Add() {
	c.mu.Lock()         // Python：with self.lock:
	defer c.mu.Unlock()
	c.n++
}

7.4 并发的 5 条规则

  1. 每个 goroutine 都要有退出的办法：要么任务做完，要么 ctx 被取消。
  2. channel 由写入的一方关闭，读的一方不要关闭。
  3. 会阻塞或者运行时间长的函数，第一个参数是 ctx context.Context。
  4. 不要把 ctx 存进结构体，每次调用时传进去。
  5. 能用“一个 goroutine 独占一份数据”解决的，就不要用锁。

go test -race 能找出数据竞争，也就是多个 goroutine 同时读写同一份数据而没有加锁。但它需要 cgo，在 Windows 上要装 C 编译器，所以以后放在 Linux 的 CI 里跑。

8. 测试

  • 测试文件以 _test.go 结尾，和被测的代码放在同一个目录。
  • 测试函数的名字以 Test 开头，参数是 t *testing.T。
  • Go 没有 pytest 那样的 assert 关键字，要自己写 if 判断：t.Errorf 记录失败，测试继续往下跑；t.Fatalf 记录失败，并立刻结束这个测试。
  • t.Run 开一个子测试。t.TempDir() 给一个临时目录，测试结束后自动删除，相当于 pytest 的 tmp_path。

8.1 表格形式的测试

Go 最常见的测试写法：把多组输入和期望结果写成一张表，循环跑一遍。作用相当于 pytest 的 @pytest.mark.parametrize。 

func TestDivide(t *testing.T) {
	tests := []struct {
		name    string
		a, b    float64
		want    float64
		wantErr bool
	}{
		{name: "normal", a: 6, b: 3, want: 2},
		{name: "zero", a: 1, b: 0, wantErr: true},
	}
	for _, test := range tests {
		t.Run(test.name, func(t *testing.T) {
			got, err := divide(test.a, test.b)
			if (err != nil) != test.wantErr {
				t.Fatalf("divide() error = %v, wantErr %v", err, test.wantErr)
			}
			if got != test.want {
				t.Errorf("divide() = %v, want %v", got, test.want)
			}
		})
	}
}

9.1 JSON 和结构体标签

Python 的 json.loads 得到一个 dict，字段随便取。Go 一般先定义结构体，再把 JSON 解析进去。结构体字段后面反引号里的内容叫标签，json:"name" 告诉 encoding/json 这个字段在 JSON 里叫什么。这和 Python 的 pydantic 模型思路相近。 

type ToolCall struct {
	ID    string          `json:"id"`
	Name  string          `json:"name"`
	Input json.RawMessage `json:"input"`          // 先不解析，原样保留
	Note  string          `json:"note,omitempty"` // 为空时不写进 JSON
}

var call ToolCall
if err := json.Unmarshal(data, &call); err != nil {
	return err
}
out, err := json.Marshal(call)

10. 常见的坑

下面这些是从 Python 转过来时最容易踩的，有几条也和 C 的习惯有关。

10.1 len 算的是字节数，不是字数

Python 的 len("你好") 是 2。Go 的字符串是 UTF-8 字节，len("你好") 是 6，因为一个中文字通常占 3 个字节。 

fmt.Println(len("你好"))                    // 6
fmt.Println(utf8.RuneCountInString("你好")) // 2
for i, r := range "你好" {                  // range 按字符遍历，i 是字节位置
	fmt.Println(i, string(r))
}

截断模型输出、统计字数时要注意这一点。按字节截断，可能把一个中文字切成两半。

10.2 切片的截取不复制数据

Python 的 a[1:3] 会复制出一个新列表。Go 的 a[1:3] 和 a 共用同一块内存，改一个，另一个也变。 

a := []int{1, 2, 3, 4}
b := a[1:3]
b[0] = 99
fmt.Println(a) // [1 99 3 4]

c := slices.Clone(a[1:3]) // 要独立的副本，就复制一份

append 也有同样的问题：两个切片可能共用后面的空间。

10.3 整数除法和溢出

  • Python 3 的 7 / 2 是 3.5。Go 里两个整数相除，结果还是整数：7 / 2 是 3。和 C 一样。
  • Python 的整数没有上限。Go 的 int 在 64 位系统上是 64 位，超出范围会绕回去，不会报错。
  • 数字类型之间不会自动转换。int 和 float64 相加之前，要先写 float64(n)。

10.4 map 的遍历顺序是随机的

Python 3.7 起，dict 按插入顺序遍历。Go 的 map 每次遍历的顺序都可能不同。需要固定顺序时，先把键取出来排序：

keys := slices.Sorted(maps.Keys(prices))
for _, key := range keys {
	fmt.Println(key, prices[key])
}

10.5 往 nil map 里写会崩溃

var m map[string]int
m["a"] = 1 // panic：map 没有初始化

m = map[string]int{} // 先初始化，或者用 make(map[string]int)
m["a"] = 1

10.6 装了 nil 指针的接口不等于 nil

func find() error {
	var p *MyError = nil
	return p // 返回的接口里装着一个 nil 指针
}

fmt.Println(find() == nil) // false

没有错误时，直接写 return nil，不要返回一个类型化的 nil 指针。

10.7 := 可能新建了一个同名变量

var err error
if cond {
	_, err := os.Open("x") // 这里新建了一个 err，外面的 err 没变
	_ = err
}
// 外面的 err 仍然是 nil

想给外面的变量赋值，用 =，不要用 :=。

10.8 其他几个坑

  • 用 _ 接住 err，就等于把错误丢掉了。审查代码时要留意 x, _ := ... 这种写法。
  • HTTP 响应的 resp.Body 必须关闭，一般紧跟着写 defer resp.Body.Close()。
  • bufio.Scanner 默认一行最多 64KB。模型的流式输出可能更长，要用 scanner.Buffer 调大。
  • JSON 解析到 any 里时，所有数字都变成 float64。
  • 格式化时间要用参考时间 2006-01-02 15:04:05 来写格式，比如 time.Now().Format("2006-01-02")。这和 Python 的 %Y-%m-%d 完全不同。
  • 没用到的 import 和变量会导致编译失败。
  • 在循环里用 += 拼接很多字符串会很慢，用 strings.Builder。
  • Go 1.22 起，for 循环的变量每一轮都是新的。网上旧文章说的“闭包捕获循环变量”问题，现在已经不会出现。

11. 审查 AI 写的 Go 代码

AI 写完一段 Go 代码后，按这张清单逐项看。

# 检查什么 为什么
1 每个返回的 err 都处理了，往上返回时用 %w 加了说明 漏掉的错误会让问题无声无息地出现
2 会阻塞的函数第一个参数是 ctx，而且函数里真的检查了 ctx 否则用户点了停止也停不下来
3 每个 goroutine 都有退出的办法 停不下来的 goroutine 会一直占用内存
4 文件、HTTP Body、子进程都用 defer 关闭或回收了 否则会泄漏资源
5 没有包级别的、会被修改的全局变量 全局状态让测试互相干扰，也难以理解
6 接口小，并且定义在使用它的包里 这样依赖方向清楚，测试也好写
7 首字母大写的名字都有注释 其他包会用到它们，要说清楚怎么用
8 有测试，而且测试覆盖了出错的情况 只测成功的情况不够
9 没有加新依赖；如果加了，有理由 项目规定优先用标准库
10 gofmt 和 go vet 都通过 pnpm --dir apps/merak typecheck 会检查这两项

练习 2 的参考答案：读取 SSE 流，并用假服务器测试

SSE 是服务器向客户端持续推送数据的一种格式，每条数据以 data: 开头。多数模型服务商的流式接口都用这种格式。

sse.go

package sse

import (
	"bufio"
	"context"
	"fmt"
	"net/http"
	"strings"
)

// Read 发送 GET 请求，返回 SSE 流里每一条 data 的内容。
func Read(ctx context.Context, url string) ([]string, error) {
	req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
	if err != nil {
		return nil, err
	}
	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		return nil, err
	}
	defer resp.Body.Close()
	if resp.StatusCode != http.StatusOK {
		return nil, fmt.Errorf("unexpected status %s", resp.Status)
	}
	var data []string
	scanner := bufio.NewScanner(resp.Body)
	scanner.Buffer(make([]byte, 0, 64*1024), 1024*1024) // 单行最长 1MB
	for scanner.Scan() {
		if value, ok := strings.CutPrefix(scanner.Text(), "data: "); ok {
			data = append(data, value)
		}
	}
	return data, scanner.Err()
}

sse_test.go

package sse

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"slices"
	"testing"
)

func TestRead(t *testing.T) {
	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "text/event-stream")
		for _, word := range []string{"hello", "merak"} {
			fmt.Fprintf(w, "data: %s\n\n", word)
		}
	}))
	defer server.Close()

	got, err := Read(context.Background(), server.URL)
	if err != nil {
		t.Fatal(err)
	}
	if want := []string{"hello", "merak"}; !slices.Equal(got, want) {
		t.Errorf("Read() = %q, want %q", got, want)
	}
}
